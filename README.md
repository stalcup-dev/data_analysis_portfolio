## Featured Project: Revenue Integrity Control Room Prototype

> **Operating question:** Which open exceptions create the most preventable revenue leakage, who owns the next action, and how much is still recoverable?

### Shipped Output

| Signal | Result |
|---|---:|
| Open exceptions surfaced | **24** |
| Gross exposure identified | **$13.37K** |
| Still recoverable | **72.9% — $9.74K** |
| Already lost | **27.1% — $3.63K** |
| SLA-breaching exceptions | **70.8%** |
| Top active queue exposure | **~63% — $8.4K** |
| Realism validation | **22 / 22 checks passed** |
| Routing history coverage | **100%** |

### Evidence Chain

| Workflow step | What the system tracks |
|---|---|
| Performed activity | A visit, procedure, lab, or service that should create a billable opportunity |
| Expected charge opportunity | What should have been captured or reconciled |
| Actual charge state | Missing, held, denied, underdocumented, or already lost |
| Failed control | The process checkpoint that did not catch the issue |
| Current blocker | Documentation, coding, billing hold, payer issue, or eligibility problem |
| Owner | The queue or function responsible for the next move |
| Recoverability | Whether the case is still financially recoverable |
| Next action | Specific follow-up path instead of a vague dashboard alert |

### What this demonstrates

- Converts claims-integrity and AR-risk data into an **owner-routed operating queue**.
- Prioritizes follow-up by **recoverability, aging, exposure, failed control, and blocker type**.
- Keeps case-level evidence consistent across the summary view, proof artifacts, and exported memo.
- Uses public-safe synthetic data because healthcare data cannot be shared publicly; the emphasis is reproducible logic, traceability, validation, and workflow realism.

## How I Work

| Principle | What it means in my projects |
|---|---|
| **Deterministic first** | I prefer transparent rules, explainable classifications, and traceable calculations before predictive modeling. |
| **Workflow before dashboard** | I design outputs around ownership, blockers, SLAs, and next actions — not just charts. |
| **Public-safe by design** | Healthcare data cannot be exposed publicly, so I use synthetic/public datasets while preserving realistic operating logic. |
| **Evidence over adjectives** | Every major claim is backed by a metric, artifact, case study, screenshot, or reproducible pipeline output. |
| **Decision-ready delivery** | I package findings as case studies, exported memos, proof tables, and stakeholder-facing summaries. |
